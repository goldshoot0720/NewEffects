- 日文原文：歌ネット（uta-net.com/song/400331）公開歌詞，未改寫；依實際唱出的樂句拆成 60 句，重複的「押せ！」保留四段。

## 字幕時間軸

`timings-ja.json` 是整句字幕的共同時間軸；`final: true` 表示輸出 SRT 時不再額外提前或延長，不代表已經通過人耳核對。2026-11-18 再次檢查原音切片，修正第一段「ドル円ロング」起點、後段漏掉的兩次「追証だ」、英文尾段提前填完，以及結尾重複喊聲的累積偏移。約 97–105 秒的三句相似對話，辨識結果無法可靠區分，仍需人耳確認，暫保留原句框。

```bash
node tools/build-fx-fill.mjs
node tools/test-fx-fill.mjs
```

## 逐字填色

`fill-ja.json` 記每句的起唱／唱完，以及每個字（空白與標點不算）唱到的時間，兩個播放器共用。

- 目前由 `node tools/build-fx-fill.mjs` 同時重建逐字填色、句框及 SRT，避免只更新填色而仍播放舊字幕。`tools/measure-fx.py` 是先前的能量分析工具，不再作為最後重建步驟。
- `fill-overrides.json` 保存長音和樂句錨點；樂句內的字以插值分配，並非每個字都由 ASR 辨識。後段 `押せ` 的原音重複週期約 0.62 秒，四組各八次分開定錨。和聲及最後兩個數字的字內分配仍是估計。
- ASR 只辨識到句中一部分時，不能藉此丟掉句首喊聲或句尾；採用 ASR 的句子必須同時涵蓋前後端。逐字時間限制在共同句框內，兩端與 SRT 一致。
- 填色的字數規則跟 `LyricText.clean` 一致：空白、標點與符號（`\p{P}\p{S}`）都沒有時間。`pv.js` 的 `attachFill` 原本把標點、`・`、`!!!` 都算成字，逐字時間對不上就整句丟掉（舊資料只有 3 句，且時間還停在換行前的位置），現在改為逐字跳過 `\p{P}\p{S}`，60 句都套得上；同一支程式也把〈Forever＆ever〉的 43 句從 32 句補到全數套用。
- 檢查：`node tools/test-fx-fill.mjs` 驗證 60 句的字數、順序、時間範圍、句框不重疊，以及 SRT／逐字填色／時間軸三者一致，並檢查後段喊聲與英文尾段的回歸錨點。這些結構檢查不能取代人耳對時。
